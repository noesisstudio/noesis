Bynoesis · Manual de diagnóstico técnico

Dónde vive cada cosa

La misma guía de diagnóstico, con el archivo, la función y la tabla concreta al lado de cada explicación. Para señalar un fallo con precisión, o para dárselo a quien vaya a tocar el código.

Verificado sobre main, esquema 50. La versión sin jerga es Diagnostico.pdf.

1. Levantar el proyecto desde cero

Lo mínimo para tener Bynoesis corriendo en una máquina limpia.

git clone https://github.com/noesisstudio/noesis
cd noesis
py -m venv .venv
.\.venv\Scripts\Activate.ps1        # Windows
pip install -e .
noesis-web                          # http://127.0.0.1:8000

Extras opcionales, según lo que vayas a tocar:

pip install -e ".[test]"       # pytest y hypothesis
pip install -e ".[analysis]"   # regenerar el modelo económico
pip install -e ".[security]"   # ruff, bandit, detect-secrets
pip install -e ".[audio]"      # transcripción local con faster-whisper
Sin DATABASE_URL usa SQLite en un archivo local, y el esquema se aplica solo al arrancar. Con ella, PostgreSQL. Para trabajar sin tocar tus datos, apunta NOESIS_DB_PATH a otro archivo.

2. El recorrido de una petición

Cuatro puertas, en este orden. Saber en cuál cae el rechazo es el diagnóstico.

PuertaDónde viveQué hace si rechaza
Identidad web/auth.py → current_user Limpia la sesión y redirige a /login. Comprueba session_version y que la cuenta esté activa
Aislamiento web/deps.py → auth_guard Compara el negocio del usuario con el de la URL. Redirige a su panel, o 403 en /api/
Permisos del plan adapters/billing.py → entitlements_for Redirige a suscripción con status=upgrade
Estado de la suscripción db.py → subscription_allows_access Deja leer, bloquea escribir. Es el modo consulta

El punto que no se puede tocar a la ligera

auth_guard es el único sitio que autoriza /b/ y /api/ en todo Bynoesis. Es la garantía de aislamiento entre negocios: un cambio ahí afecta a todos los clientes a la vez.

Antes hay tres middlewares más, en este orden inverso al de declaración: security_headers, canonical_public_host y request_observability. Un 403 raro con origen correcto suele venir de la comprobación CSRF por cabeceras, en csrf_response.

Por qué importa la carpeta adapters/: todo lo que depende de un tercero está detrás de uno. Si algo externo falla, el fallo está ahí y no repartido por el producto. Es el primer sitio donde mirar cuando el síntoma involucra a un proveedor.

4. Las colas

Nada se envía en caliente. Todo pasa por una cola durable, y ahí es donde se ve qué falló.

ColaTablaEstados
Correoemail_outboxqueued → processing → sent / retrying / failed
WhatsAppwhatsapp_outboxIgual, más delivered y read desde Meta
Veri*FactuCola propia con reintentosAceptada, rechazada, con errores

Reintento con espera creciente de 30 s a 1 h, seis intentos. La idempotency_key impide que el mismo aviso salga dos veces. En WhatsApp la cola guarda además connection_id, así que un reintento sale por el mismo número que recibió el mensaje.

Para diagnosticar: db.admin_support_delivery_failures(business_id) devuelve canal, estado, intentos y el error del proveedor, sin exponer destinatario, asunto ni cuerpo. Es lo que pinta «Entregas atascadas» en la ficha de la cuenta.

7. Comprobaciones rápidas

curl https://bynoesis.com/health   # vivo + release desplegado
curl https://bynoesis.com/ready    # + esquema aplicado

Si /ready devuelve un esquema distinto al de project-state.json, hay un despliegue a medias: ese es el fallo y no lo que te esté contando el cliente.

python -m pytest tests/ -k "whatsapp"   # acotar por área
python -m ruff check src/               # errores reales, no estilo
En Windows fallan tres o cuatro pruebas con PermissionError [WinError 32] al borrar el temporal: SQLite mantiene el archivo abierto. El cuerpo de la prueba pasó; falla la limpieza. En el CI, que corre en Linux, no ocurre. No lo persigas.

8. Invariantes que no se rompen

Si alguna vez ves lo contrario, no es un caso raro: es un fallo grave.

  • Toda consulta filtra por business_id. Sin excepción.
  • Una factura emitida no se modifica. Se corrige con una rectificativa.
  • Nada que mueva dinero se ejecuta sin confirmación del titular.
  • La bitácora de seguridad es encadenada: cada entrada firma la anterior.
  • Administración no abre el negocio de un cliente. Gestiona acceso, no contenido.
  • El cerebro local sigue disponible aunque toda IA externa falle.
